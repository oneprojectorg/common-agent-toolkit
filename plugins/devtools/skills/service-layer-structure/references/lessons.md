# service-layer-structure: lessons

- `phaseBinding` read `process.phaseIds` before `writeWithPhaseLock`; a concurrent phase removal slipped through. Re-read inside, and test the disagreeing case (PR #2095)
- Fix used `SELECT … FOR UPDATE` on the instance row because the builder writes `instanceData` with a plain `UPDATE`; state the lock order (advisory then row) (PR #2095)
- `removeDecisionPublicAccess` discarded `lockProcessInstance`'s miss and returned 200 where `makeDecisionPublic` returns 404 (PR #2124)
- `updateReview` checked the current phase in JS only; the `WHERE` guarded `state = SUBMITTED` alone (PR #1703)
- The concurrent-failure path gets its own `ValidationError('Review state changed concurrently; …')` (PR #1703)
- Unique index on source alone let two merge edges commit (PR #1789)
- A↔B concurrent merges formed a cycle every unique index allowed; needs an advisory lock over the sorted pair (PR #1860)
- `assignPhaseReviews` skipped `assertInstancePhase`, which its read sibling calls; it created unreachable rows (PR #1848)
- `CUSTOM_FORM_DEFINITION_MAX_BYTES` used `String.length`; the sibling `..._SUBMISSION_MAX_BYTES` was fixed in the same PR (PR #2095)
- Lowered heading/description caps made existing forms unsavable (PR #2168)
- `profiles.email` is null for most reviewers; disambiguate on `slug` (PR #1848)
- `listProposalFeedback` sorted/filtered in memory; secondary reads may ship unpaginated if the bound is stated and a follow-up is filed (PR #1815)
- `useProposalFilters` filtered after paging, so counts and empty states were wrong; move the filter to the API (PR #1923)
- `includeMemberCount` flag kept by enumerating the callers that would pay the COUNT (PR #1721)
- Flags that choose behaviour should be split ops (PR #1084)
- `getDecisionReviewAssignments` went from admin-only to a tab refetching on every `reviewAssignments` broadcast; split per consumer, then page (PR #1848)
- A moderation flag row written before the Checkstep call survived a failure and blocked all later reports (PR #1843)
- Export status cache cast with `as`; moved to a shared `exportStatusRecordSchema`, `safeParse`, and treated a miss as "cannot patch" (PR #1851)
- CSV formula injection via custom-field values in `exports/generateProposalsCsv.ts`; still unescaped on `dev` as of 2026-10-07 (PR #1852)
- "Export all" made one `listProposals` call and dropped `hasMore` (PR #1824)
- The truncation branch logged but returned `truncated: false`, so no banner appeared (PR #1803)
- A missing new taxonomy term returned early with no log line, which reproduced the orphaning bug (PR #1677)
- The newest assignment pointed at a removed phase and returned a 404 for a reachable proposal (PR #1774)
- `export *` leaked `ensureProposalTaxonomyTerms` from `@op/common` (PR #1676); document caller contracts on promoted helpers (PR #1680)
- Sequential awaits that could be `Promise.all` (PR #1320); re-fetch of a row the assert already had (PR #1320)
- Provider caps: OpenL texts per request (PR #1523); DeepL 50 params, one text per request with bounded concurrency (PR #1533)
- Short-circuit an always-empty scope with `isEmpty` (PR #1437); push membership into a subquery (PR #1437); use `EXISTS` for the category filter (PR #1551)
- A join on proposals flattened accounts and was how `listProposalRelationships` leaked anonymous authors (PR #1856)
- Eager `LEFT JOIN LATERAL` scanned about 20k rows for a page of 10; page ids first (PR #1516)
- Cursor ties on `createdAt` skipped rows; `cursorValue` truthiness broke on score 0 (PR #1304)
- Helpers don't need their own file; check `utils/phaseSettings.ts` / `utils/phaseOrder.ts` first, or delete the wrapper (PR #1856, #1961)
- `x-phase` was added both in `customForm.ts` and via `ajv.addKeyword` (PR #1532)
- The content-key format change re-translated array fields once (PR #1540)
- The shared filter builder was lifted out of `listProposals` for the map endpoint (PR #1553); the third inline moderation copy should fold into `phaseEligiblePredicate` (PR #1848)
- Inline fetch-then-check flagged repeatedly; use `<feature>Auth.ts` (PR #1229)
